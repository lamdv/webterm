# webterm desktop client

A Tauri client for remote webterm servers. It stores server profiles and opens
one window per server, pointed at that server's own web client — so the app and
the browser show exactly the same UI.

This app does **not** run a server. `localhost` is simply one more profile.

## Layout

```
Cargo.toml              cargo workspace (two members)
rust-toolchain.toml     pins stable + rustfmt + clippy
crates/webterm-client/  portable logic: profiles, persistence, auth (no Tauri)
src-tauri/              the Tauri shell: windows, IPC, plugins
frontend/               the picker page (plain HTML/CSS/JS, no build step)
tutorial/               read this to learn the codebase and Rust
```

The split matters: anything testable without a window goes in
`crates/webterm-client`, which is what will let the same code compile for iPad
and Android later.

## Build

Prerequisites: `rustup`, the Tauri CLI, and the platform webview libraries
(Linux: `webkit2gtk-4.1`). See [tutorial/00-orientation.md](tutorial/00-orientation.md)
for the exact commands.

```bash
cargo test -p webterm-client   # fast: no window, no Tauri
cargo tauri dev                # run the app
cargo tauri build              # produce bundles
```

## Why the terminal UI is not in this repository

When you connect, the window navigates to the server's origin and loads the
server's `index.html` / `app.js` / `style.css`. Keeping the webview on the
server origin (rather than building our own terminal UI) is deliberate: it keeps
the session cookie and the WebSocket first-party and same-origin, which is what
makes OAuth2 proxies such as oauth2-proxy work without any server-side change.

The picker therefore cannot share a stylesheet with the server (different
origin, no CORS), so `frontend/picker.css` carries its own copy of the palette,
intentionally matching `webterm/static/style.css`. If you change one palette,
change the other.

## Security

- `capabilities/default.json` grants IPC to the `main` (picker) window only.
  Server windows are not listed, so a remote page cannot reach the app's IPC.
  This is enforced by the app ACL manifest declared in `build.rs`
  (`permissions/autogenerated/`), not just by the comment in the capability.
- `withGlobalTauri` is off, so there is no ambient `window.__TAURI__`. The
  picker reaches Rust through `frontend/ipc.js`, a one-function wrapper over the
  `window.__TAURI_INTERNALS__.invoke` bridge that the official API also uses.
- Remote windows are given exactly one server and navigate to it; they receive
  no app-level privileges.

## Profiles

Saved servers live in the per-app config directory
(`app_config_dir()/servers.json`, e.g. `~/.config/dev.webterm.desktop/` on
Linux). The file is written atomically and chmodded to `0o600` because a token
profile stores its secret there. Profiles can be added, edited and removed from
the picker; an edit keeps the profile's id.

## Authentication

- **Open** profiles navigate straight to the server.
- **Token** profiles navigate once to `/?bootstrap=<token>`; the server trades
  the secret for an `HttpOnly`, `SameSite=Strict` cookie and redirects to `/`,
  so the WebSocket authenticates with the cookie rather than a token in its URL.
- **Browser login** profiles send no credential and let an identity-aware proxy
  (oauth2-proxy, Authelia) run its own login in the window.

The URL-building rule lives in `crates/webterm-client/src/connect.rs` and is
unit tested there.

## Server status

Each row is probed against the server's unauthenticated
`/.well-known/webterm.json` document using the `reqwest` client re-exported by
`tauri-plugin-http`. A probe that fails or a protocol this client does not know
shows as offline or incompatible, with the reason in the tooltip. The document
shape and the discovery URL rule live in
`crates/webterm-client/src/discovery.rs`.

## Menu and shortcuts

A native menu (`src-tauri/src/menu.rs`) provides **New Server** (Cmd/Ctrl+N),
**Reload Window** (Cmd/Ctrl+R), plus predefined Quit, Minimize, Fullscreen and
Close Window items. It is native so it also appears in server windows showing a
remote page. Copy/Paste items are deliberately absent: their default Ctrl+C /
Ctrl+V accelerators would swallow the terminal's SIGINT and paste keys.

## Window state

`tauri-plugin-window-state` remembers each window's size, position, maximized
and fullscreen state in `app_config_dir()/.window-state.json`, keyed by window
label. Server windows are restored because their label is derived from the
profile id, which is stable across renames.
